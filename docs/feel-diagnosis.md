# 手感问题诊断速查表：把体感翻译成代码指令

> 贴给 OpenCode / Space Bunny 用。原则：不说"优化手感"，说"查参数 X，改成 Y，因为 Z"。

## 翻译流程（每次手感不对，走一遍）

1. **定性**：一句话说出体感（不跟手 / 阻力大 / 慢半拍 / 飘 / 一顿一顿 / 小拖不动）。
2. **量化**：能录屏数帧就数帧，能实测就测（如"2 秒拖 150px，角色只走了 30px"）。没有数字，所有猜测都是玄学。
3. **定位环节**：输入（摇杆/触摸）→ 模拟（速度/碰撞/时间步进）→ 渲染（帧率）。一次只怀疑一个环节。
4. **读代码找参数**：定位到具体参数再下指令。
5. **一次改一处**，真机拇指复验。桌面浏览器测过不算数。

## 体感 → 根因 → 给 AI 的指令

### 不跟手（推了，角色反应小）
- 查：摇杆满速半径（相对屏幕宽度是否过大）、死区大小、速度映射曲线前段。
- 指令示例："检查摇杆归一化：满速半径改为屏幕宽度的约 1/7；死区≤4px；速度曲线用 pow(t,0.45)，让小位移也有速度。"

### 阻力大（像在水里 / 像在人群里挤）
- 查：碰撞击退、摩擦/减速系数、基础移速。
- 指令示例："检查移动中是否触发碰撞击退；原型阶段可先关闭碰撞反馈；基础移速提到 X。"

### 慢半拍（手指动了，角色晚到）
- 先量化：录屏对比手指位移与角色位移是否同步。
- 查：帧率（渲染开销：DPR、全屏渐变/阴影）、dt 处理（单帧 dt 钳制会导致低帧率时慢动作）。
- 指令示例："帧率低于 20 时游戏是否变慢动作？改定步长子步进（1/60）；DPR 上限 2；全屏渐变烘焙为静态离屏 canvas。"

### 飘（松手还滑，收不住）
- 查：松开摇杆后的速度衰减（摩擦力）、摇杆回中逻辑。
- 指令示例："松开摇杆后，速度应在 0.15 秒内衰减到 0；检查回中动画是否插值到了错误坐标。"

### 一顿一顿（抖）
- 查：帧率稳定性、每帧渲染开销、是否每帧创建对象（GC 抖动）。
- 指令示例："把静态背景/精灵预渲染到离屏 canvas，每帧只做 drawImage；避免在循环内 createGradient / new 对象。"

### 小拖不动（轻推没反应，大推才走）
- 查：摇杆增益曲线。
- 指令示例："速度曲线前段调陡（如 pow(t,0.45)）：推 10px 即半速。"

## 下指令铁律

- 一次只改一个参数。
- 改完必须真机复验，拇指是唯一验收仪器。
- 先定位环节再动手：输入、模拟、渲染，一次只动一个。
