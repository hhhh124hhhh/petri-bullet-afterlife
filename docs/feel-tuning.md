# 手感调优方法论（Prototype 0 实录）

> 2026-10-07，petri-bullet-afterlife。Prototype 0 只验证一件事：手机单手移动有没有摩擦。
> 验收标准：制作人的拇指。代码审查、桌面浏览器测试全过不算过，拇指说过才过。

## 四轮迭代实录

### 第一轮：不跟手
- 反馈："移动不算跟手"
- 查代码发现：摇杆响应半径 70px，在 360px 宽的屏幕上要拖近 1/5 屏宽才满速；日常划 20–30px 只有四成速度，所以感觉"肉"。
- 改：响应/视觉半径统一 50px，移速 110→125。

### 第二轮：阻力大
- 反馈："不够丝滑，阻力很大"
- 查代码发现：敌人环形包围玩家，移动中撞上敌人每次被弹开 6px——等于在人群里挤，阻力就是这么来的。
- 改：P0 只测移动，关闭碰撞击退（碰撞/伤害留给 Prototype 1）；响应曲线改 pow(t,0.7)；移速 150。

### 第三轮：慢半拍
- 反馈："还是有点阻塞" → 用三选一问出是"手指动了、角色慢半拍才跟上"（输入延迟）。
- 量化：浏览器实测 2 秒拖 150px，角色只走了预期的约 1/7。
- 根因有二：
  1. 单帧 dt 钳在 0.05s——帧率低于 20fps 时，游戏时间比真实时间慢，全员慢动作；
  2. 手机端 DPR 3（约 590 万像素）+ 每帧全屏渐变 + 26 条网格线，正是掉帧元凶。
- 改：DPR 上限 2、背景离屏烘焙、敌人/玩家预渲染成精灵、touchmove 取合并事件最新位置、定步长子步进（1/60，帧率再低速度也与真实时间一致）。

### 第四轮：小拖不动
- 反馈："确实好些了，还是不够丝滑"
- 40 秒 soak 实测：慢速小幅度拖拽角色只走一点点——摇杆"推多远跑多快"的前段太软，轻推=爬。
- 改：增益曲线改陡 pow(t,0.45)，推 10px 即半速，推 20px 约三分之二速。
- 拇指验收通过 ✅

## 方法论（可复用）

1. **拇指是唯一的验收仪器。** 手感没法靠代码审查或桌面测试判断，必须真机亲手试。这个版本桌面端全过，手机上连跪三轮。
2. **一次只动一个变量。** 每轮只改一处（或一类），反馈才能对应到原因；否则不知道是哪一改起的作用。
3. **把主观变成数字。** "慢半拍"→实测"2 秒拖拽只走了 1/7"，数字直接指向 dt 钳制。感觉能量化，就能量产。
4. **卡住时问选择题，不问开放题。** "阻塞"太宽，用三选一（画面一顿一顿 / 手指动角色慢半拍 / 怪堆里挤）一次收窄。
5. **读代码，不猜。** 每个根因都来自逐行读代码：70px 半径、6px 击退、0.05s 钳制、pow 曲线。调参碰运气不如读代码。
6. **区分正确性 bug 和调参。** dt 钳制是正确性 bug（游戏时间≠真实时间），增益曲线是调参。两类问题解法不同，混在一起调会越调越乱。
